# v0.5.0 — Phase 4: Dual Python authority

Phase 4 introduced native uv as a first-class Python authority while retaining Conda.

The scaffold now supports `authority = "uv"` and `authority = "conda"` behind the same Makefile contract. Native uv became the reusable-scaffold default, managed-Python discovery/bootstrap and authority-specific provenance were added, dispatcher/sync/lock/doctor behavior became authority-aware, and CI expanded to Linux/Windows × Conda/uv.

CI also exposed a provenance regression in native-uv discovery: once `.venv` existed, discovery could resolve it instead of the source managed Python. The fix made `--system` part of the uv authority invariant.
