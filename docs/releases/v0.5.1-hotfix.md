# v0.5.1 — Windows env-rebuild hotfix

This patch fixes the Windows destructive-rebuild path discovered during real-machine validation on Pangaea after Phase 4.

With an active project `.venv`, `make env-rebuild` originally attempted to delete the same `.venv\Scripts\python.exe` that was executing `scripts/repo.py`, producing `PermissionError: [WinError 5] Access is denied`.

The first fix released the lock through process replacement, but exposed a second bug: PowerShell regained the prompt before the replacement process had finished, causing prompt/output interleaving.

The final design keeps PowerShell as the foreground parent, resolves a safe authority Python outside the project `.venv`, lets the short resolver exit to release the Windows executable lock, then runs the complete rebuild and waits through bootstrap, sync, and doctor.

Validated by CI and on Pangaea with an active `.venv`: no WinError 5, no premature prompt, exit code 0, matching uv provenance, and `Environment contract: OK`.
